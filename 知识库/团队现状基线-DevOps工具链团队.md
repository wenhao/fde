## 一、团队职责

团队是一个**软件开发团队**，负责公司**内部 DevOps 工具链**的开发。

### 产品矩阵

| 产品线 | 所属环节 | 典型功能 |
|---|---|---|
| **需求管理** | 研发上游 | 需求收集、拆解、流转、跟踪 |
| **研发一站式工作台** | 研发主链路 | 打通需求→开发→测试→发布的统一入口与集成层 |
| **代码检视** | 研发质量关 | Code Review 流程、检视规则、协作评审 |

三条产品线串起来即公司内部的**研发效能工具链**，服务对象是公司内部研发人员（内部客户）。

## 二、团队角色与职责

| 角色 | 核心职责 | 对外接口 |
|---|---|---|
| **产品经理** | 产品需求分析、产品规划 | 内部用户的需求入口 |
| **技术经理** | 产品技术架构、技术栈选型、团队管理 | 技术决策与团队资源 |
| **后端 Java 开发** | 具体后端编码 | — |
| **前端 React 开发** | 具体前端编码 | — |
| **测试人员** | 手工测试、自动化测试 | 质量把关 |

## 三、基线特征（转型分析用）

从转型视角看，这个团队有几条显性特征：

1. **典型的"内部工具型"软件团队**——按产品线组织职能分工，交付形态是"产品功能"，不是"业务结果"。
2. **客户就在公司内部**——距离近、反馈快，天然具备 FDE 所要求的"贴身前线"条件，但也容易因为"太熟"而缺少正式的客户经营动作。
3. **角色是经典瀑布式分工**（产品/技术/前后端/测试），与 FDE 的"一人多能、端到端负责"模式差异明显——这是转型的主要张力，也是方案的改造对象。
4. **AI 含量未提及**——基线中无 AI 相关能力与资产，可视为从零起步。
